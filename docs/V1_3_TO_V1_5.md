# AI Factory v1.3–v1.5

## v1.3 — Closed-loop CAD

Goal: turn an engineering objective into a Fusion edit/inspection cycle.

1. Generate a typed engineering plan.
2. Inspect the current Fusion state.
3. Perform the smallest required CAD changes.
4. Inspect after modification.
5. Produce evidence-backed output.
6. Repeat within a bounded iteration budget when unresolved conditions remain.

No manufacturing or physical machine dispatch is included in this milestone.

## v1.4 — Verification and production preparation

The system records requirements, plans, verification evidence and BOM/work-order data. Manufacturing actions remain approval-gated. A work order is created in `awaiting_approval` and is never dispatched by the language model itself.

Future verification adapters should report machine-readable measurements rather than relying on prose alone.

## v1.5 — Factory control plane

The API exposes a factory-cycle endpoint and work-order endpoints. The UI surfaces the cycle runner. Local Qwen remains the default provider through the existing provider abstraction.

### Next hardware adapters

- 3D printer adapter: slice/export only until approval is granted.
- CNC adapter: toolpath generation and dry-run validation before execution.
- Vision adapter: camera measurements against explicit requirements.
- Inventory adapter: BOM availability and sourcing status.
- Test-rig adapter: telemetry and pass/fail evidence.

The critical architectural rule is that AI can propose and verify engineering actions, while irreversible physical execution remains an explicit, auditable state transition.
